# Axophyte

## Before deploying

- Add `secrets.service.discord.axophyte.{token,tavily}` in git-crypt `mix/secrets.nix`. These values enter the Nix store under the repo's existing secrets convention.
- In the Developer Portal, enable **Message Content Intent** and **Server Members Intent** (both privileged); without them login fails. [Invite the bot](https://discord.com/oauth2/authorize?client_id=1557540580962336848&scope=bot+applications.commands&permissions=274877973568) to each server.
- List each server in `servers` in [`default.nix`](default.nix): guild ID → its Axophyte forum ID, or `null` for mentions and replies only. A server the bot isn't in, or whose forum is missing, is skipped with a log line; the others still run.
- Give it View Channel, Read Message History, Send Messages (in Threads), and **Add Reactions** everywhere it should answer or search.
- Use Tavily's free Researcher plan; **do not enable pay-as-you-go**. Basic search and basic page extraction cost one credit each; free quota is 1,000 credits/month.

## Models and credentials

Every process starts on **local llama.cpp**, using `AXOPHYTE_MODEL` (`qwen3.8-27b-abliterated` in Nix). Model selection is never saved to disk. Server admins can use:

- `/model` — show the active model.
- `/model name:<autocomplete choice>` — select a configured provider's model.
- `/model name:local` — return to local inference.

Selection is **bot-wide, across all configured servers**, until another selection or restart. It covers chat, summarization, person-note pruning, emoji descriptions, and drawing. Running work keeps its original model; queued work picks the selection when it starts. Failed selections leave the active model alone; provider failures never silently fall back to another provider. Commands reply privately.

| Provider | Autocomplete ID prefix | Credential |
| --- | --- | --- |
| Local llama.cpp | `local` | None |
| Anthropic API | `anthropic/` | `ANTHROPIC_API_KEY` |
| Codex subscription | `openai-codex/` | `/codex-login` in Discord |
| DeepSeek API | `deepseek/` | `DEEPSEEK_API_KEY` |
| Gemini API | `google/` | `GEMINI_API_KEY` |

Autocomplete uses the pinned SDK's catalog, filtered to configured providers and models with enough context/output capacity. Type a provider or model name to filter it; Discord shows at most 25 matches. Updating the SDK updates this catalog. API-key presence makes a provider selectable; invalid keys, exhausted quota, or account-specific model access can still fail at inference.

**Cloud privacy and billing:** selected cloud providers receive the turn's prompt, Discord history, relevant memory/person notes, tool results, and supported attachment content. Background model jobs also use that provider. Media decoding, speech transcription, rendering, and database storage remain local. API providers charge their accounts; Codex uses an eligible ChatGPT subscription and its limits, not an OpenAI API key.

### API keys

Nix forwards any `ANTHROPIC_API_KEY`, `DEEPSEEK_API_KEY`, and `GEMINI_API_KEY` already present under `secrets.service.models` in `mix/secrets.nix`. Shared Anthropic/DeepSeek keys therefore need no duplicate entries. These values enter the Nix store under the existing secrets convention.

Alternatively, put any of those `KEY=value` lines in `/var/lib/private/axophyte/providers.env` on Zebes, owned by root with mode `0600`. This optional systemd environment file overrides shared keys without adding them to the Nix store. Restart `axophyte` after changing it; omitted providers do not affect local startup. For manual runs, export the same environment variables.

### Codex subscription login

No terminal login, SSH, or credential copying:

1. Enable **device-code login** in ChatGPT **Security** settings, or have your workspace admin enable it ([OpenAI instructions](https://developers.openai.com/codex/auth#login-on-headless-devices)).
2. Run `/codex-login` in a configured Discord server. You must be both a server administrator and the bot's Discord application owner (team owner for team-owned applications); ownership is checked directly with Discord.
3. Open the private OpenAI link, enter the displayed code, and approve in your browser. Never paste passwords or tokens into Discord.
4. When Axophyte confirms connection, use `/model` autocomplete to choose a Codex model.

The connected subscription is shared bot-wide: configured-server admins can select its models. Login itself does **not** change the active model. Credentials survive restarts; model selection still resets to local.

Only one login runs at a time. **Cancel** or the ten-minute deadline stops pending authorization and clears the private code/buttons. Existing credentials stay in use until approval. Once approval enters the saving stage, cancellation is disabled so newly issued tokens are not lost. Failures never expose provider responses or tokens.

Axophyte creates `/var/lib/axophyte/auth.json` in its service namespace, owned by the service user with mode `0600`, and atomically saves refreshed tokens there. Source refreshes preserve it. No callback port or new Nix settings are needed. Manual runs use `auth.json` in the working directory, or `AXOPHYTE_AUTH_FILE`; keep the credential file private and exclusive to Axophyte.

## Verify and deploy

From this directory:

```fish
nix run nixpkgs#bun -- install --frozen-lockfile
nix run nixpkgs#bun -- test
nix run nixpkgs#bun -- run typecheck
cd ../../../..
nix flake check
nix build .#nixosConfigurations.zebes.config.system.build.toplevel
bonk switch -H zebes
```

New source files must be tracked by git (`git add -N`) before `nix build`, or the flake drops them. Each service start installs production dependencies from `bun.lock`; registry failure can prevent startup. On Zebes, inspect `journalctl -u axophyte -b`; startup logs `ready … in N/M servers`. Memory lives in `/var/lib/private/axophyte/axophyte.sqlite`; source refreshes do not remove it.

## Behavior

- **Soul:** [`src/soul.ts`](src/soul.ts) holds identity and voice rules, distilled locally from Toph's own Discord messages: a blunt, deadpan, slightly chaotic regular in his voice who never claims to be him. Lowercase, light punctuation, one or two lines by default, about 20–60 words when explaining. No technical setup. `src/conversation/prompt.ts` owns chat formatting, speaker attribution, and trust boundaries, followed by place, date, server emoji, conversation memory, and people notes. A reaction is the minimum reply.
- **Self-knowledge:** the parameterless `self_info` tool in [`src/tools/self.ts`](src/tools/self.ts) supplies setup facts on demand: author, the model/provider actually serving the turn, local versus cloud privacy, vision capability, external services, message visibility, memory, commands, and capabilities. Facts stay out of the standing prompt; keep the tool's facts in sync with runtime behavior and this README.
- **Where it talks:** every message in its server's forum, if that server has one, and in active Discord threads (threads started from an Axophyte message or where `@Axophyte` was mentioned, where it keeps replying without needing to be mentioned again); anywhere else in a configured server, only when `@Axophyte` (or its own bot role) is mentioned or someone replies to it (no ping needed). Someone already in the current exchange can follow up without mentioning it. `@everyone` and other role pings never trigger it. A server whose member refresh fails after a reconnect is skipped until restart, including turns already queued there.
- **Bursts:** it waits until people stop sending and typing (4 s quiet, 10 s after typing, at most 45 s) and answers exactly the messages that triggered it, by ID. A message arriving before substantive text, a saved note, reaction submission, or a drawing starting restarts the wait; after that it queues separately. Reaction success is counted only after Discord confirms it; a failed submission returns a tool error without reopening the turn. Whitespace-only streamed deltas stay buffered without clearing the status notice or counting as output.
- **Status notices:** after 15 s without reply text, the reply slot shows what it's doing as subtext (`💭 thinking…`, `🗜️ catching up on older messages…`, or the running tool, such as `🔗 reading <url>…`) and updates as that changes; the first real text replaces it. Turns, note pruning, and emoji descriptions share one queue, so a turn stuck behind work in another channel (a drawing holds it for minutes) posts `⏳ busy with something else, I'll get to this soon…` after 15 s of waiting and deletes it when its turn starts; a channel whose own turn is running gets none.
- **Conversation memory:** each forum post and active thread is one conversation. Its first load reaches back at most 300 messages (joining a thread already underway) and marks where the conversation starts; from then on every message since the last summary loads, however many, and older messages compact into persistent memory only when they no longer fit the selected model's context, reserving 8,192 answer tokens plus 1,024 headroom. Local inference uses llama.cpp's exact runtime token count/context; cloud inference uses catalog context limits and a conservative UTF-8-byte estimate plus message/tool/image overhead, so it can compact earlier. Loading refetches unsummarized history from Discord each turn, 100 messages per request. Outside forums and active threads it reads the triggering messages, up to 20 messages before them from the last 30 minutes, and the reply chains they point into (up to 10 older messages); it keeps no conversation memory there.
- **Conversation view:** every trigger message gets a tag (`m1`, `m2`, …) in every channel. Consecutive human lines share one model message; Axophyte's replies stay unlabeled. Human lines show Puerto Rico time (`America/Puerto_Rico`, UTC−4 year-round), with Today/Yesterday/day-age labels on the first line and day changes; exact multiples of seven days use weeks. Search hits and calendar-date filters use the same clock. Reply quotes and reaction counts include its own reactions. Images attach to their line when supported.
- **Media:** attached images and direct image/GIF/video embeds load automatically through Discord CDN/proxies, never from the linked site or through `open_url`; article, rich, and YouTube previews stay text. Videos and animated GIFs become one 2×2 stills grid timed from the video track when available, falling back to the first frame if the grid fails. Local CPU whisper.cpp (`large-v3-turbo-q5_0`) transcribes voice messages, audio, and video sound, serialized one job at a time and limited to the first 3 minutes. Text/code files, PDFs (first 30 pages), and docx/odt/rtf/epub documents become quoted text; pptx/xlsx and binary files stay unsupported. Forwarded snapshot text and media are included. Per prompt, newest first: 4 images/grids, 4 documents (8,000 characters each), and 2 transcripts (4,000 characters each). Size caps: 10 MiB images, 50 MiB GIF/video, 25 MiB audio/documents, 1 MiB text files; items exceeding byte caps are labeled “too large,” while items beyond prompt slot budgets remain labeled “not shown.” Processor inputs stream into per-job temporary files; extracted document text is captured incrementally with bounded retention. Attachment and transcript clipping never splits UTF-16 surrogate pairs. Successful results and permanent processing failures are cached (64 entries); network failures, timeouts, and retryable partial results are retried next turn. A partial result keeps any usable image or transcript. Canceling an obsolete turn stops waiting without canceling reusable cached media work, freeing the global turn queue; temporary files stay alive until that work finishes. Local decoders accept only self-contained files, with network and playlist input formats blocked.
- **Vision capability:** determined per selected model, not per provider. Text-only models receive an explicit image-omission notice; transcripts and document text still work. Image-based emoji-description jobs are skipped until another emoji update or restart; existing descriptions and admin overrides remain usable.
- **Emoji:** custom emoji appear to the model as `:name:`; the system prompt lists up to 100 usable emoji, Axophyte's own application emoji first (uploaded in the Developer Portal, usable in every server, never cut by the limit), then the server's, each with a one-line description of what it shows or how the server uses it. Own emoji are fetched at startup only: Discord sends no events for them, so new uploads need a restart. The model writes descriptions itself by looking at each emoji (first frame if animated) and its name, one at a time on the shared queue so replies wait behind at most one. Descriptions queue at startup and on server emoji creation/update, never after ordinary chat turns; a failed item is skipped until another update or restart, without blocking later emoji. It redoes its own after a rename. An admin's `/emoji` description replaces the model's and is never overwritten. Deleted emoji lose their notes immediately; startup removes stale notes after a successful emoji refresh. Deletion or rename during inference cannot save a stale description. Descriptions live in SQLite, per server; the model's descriptions of own emoji are shared across servers, but an admin's meaning, even for an own emoji, applies only in that admin's server. When sent, `:name:` (closing colon optional, case-insensitive, one typo tolerated) becomes the real emoji, unless conversion would exceed Discord's message limit. Trailing emoji after text go out as a separate message so Discord shows them large.
- **Person memory:** per server: notes and nicknames learned in one server never load in another. It notes what people share about themselves (interests, projects, how they like to talk) as it comes up, so later conversations can build on it; only in channels every member of that server can read. Each note names the message it came from and is stored under that message's author, so nobody can write notes about someone else. Notes load wherever that person talks or is mentioned in the same server. Over 2,000 characters, the model condenses them to about 1,200, keeping what helps conversation over trivia.
- **Tools:** `react` targets a tagged trigger message with a server or unicode emoji (up to 3 per turn). Its required `reply` flag says whether a message follows. A round whose tool calls are all actions (`react`, `remember`, `revise`) ends the turn once it has written text, or reacted with `reply: false`, because forcing another round only makes the model repeat itself or pad with a lone "."; otherwise it keeps going and writes the message. Also `web_search`, `open_url` (through Tavily Extract; the bot never fetches pages itself), and `search_server` / `read_conversation`. Server search covers the current channel too (minus messages already in view) and only returns channels that everyone who can see the current channel can also read, whoever asks; it is off in private threads. Every round offers the same tools; per-turn budgets and, after 6 tool rounds, every further call are refused with an error telling the model to answer from what it has. It only gives up after 2 refused rounds.
- **Drawing:** `draw(title, prompt, revise)` hands the prompt to a separate art-only session on the turn's captured model (no chat history or persona; [`src/art/artist.ts`](src/art/artist.ts) holds the guide and prompts). It plans parts and coordinates, writes SVG, renders it locally with resvg (DejaVu fonts only), gets one repair if it won't render, then reviews the render with vision and fixes what it sees; a review that fails or won't render keeps the draft. Text-only models skip the visual review and return the rendered draft. SVG with external references (`<image>`, non-`#` `href`/`url()`, `@import`, DOCTYPE) is refused before rendering, because resvg reads local files. Local drawings take about 5–6 minutes, holding the shared queue the whole time; the draft shows on the status notice while the review runs. The reply carries the PNG and the `.svg`. `revise: true` edits the channel's last drawing, remembered in memory only (50 channels, lost on restart).
- **Commands:** `/memory show` lists your notes in this server; `/memory forget item:<number|all>` deletes them; `/emoji emoji: use:` (server admins only, checked again at runtime) sets what an emoji means in this server; its autocomplete lists the server's emoji and Axophyte's own (which admins can't pick from their emoji menu). `/retry` (server admins only, checked again at runtime) answers the channel's newest human message as if it just arrived, for when Axophyte never replied or its reply was deleted; it goes through the usual burst wait and deletes nothing, and refuses locked threads. Web searches happen through the `web_search` tool when a conversation calls for one; there is no search command. Command replies are ephemeral, so commands never enter conversation history. All servers share one model queue and one Tavily quota.
- **Model command:** `/model [name:]` is admin-only, checked again at runtime, and ephemeral. Selection is bot-wide, not per server/channel/user; see [Models and credentials](#models-and-credentials) for setup, cloud privacy, and restart behavior.
- **Codex login:** `/codex-login` connects the shared subscription through a private device code and browser approval. Requires the application owner plus server Administrator, unlike `/model`, which server admins can use.
