# Axophyte

## Before deploying

- Add `secrets.service.discord.axophyte.{token,tavily}` in git-crypt `mix/secrets.nix`. These values enter the Nix store under the repo's existing secrets convention.
- In the Developer Portal, enable **Message Content Intent** and **Server Members Intent** (both privileged); without them login fails. [Invite the bot](https://discord.com/oauth2/authorize?client_id=1557540580962336848&scope=bot+applications.commands&permissions=274877973568) to each server.
- List each server in `servers` in [`default.nix`](default.nix): guild ID → its Axophyte forum ID, or `null` for mentions and replies only. A server the bot isn't in, or whose forum is missing, is skipped with a log line; the others still run.
- Give it View Channel, Read Message History, Send Messages (in Threads), and **Add Reactions** everywhere it should answer or search.
- Use Tavily's free Researcher plan; **do not enable pay-as-you-go**. Basic search and basic page extraction cost one credit each; free quota is 1,000 credits/month.

## Verify and deploy

From this directory:

```fish
nix run nixpkgs#bun -- install --frozen-lockfile
nix run nixpkgs#bun -- test
nix run nixpkgs#bun -- run typecheck
cd ../../../..
nix build .#nixosConfigurations.zebes.config.system.build.toplevel
bonk switch -H zebes
```

New source files must be tracked by git (`git add -N`) before `nix build`, or the flake drops them. Each service start installs production dependencies from `bun.lock`; registry failure can prevent startup. On Zebes, inspect `journalctl -u axophyte -b`; startup logs `ready … in N/M servers`. Memory lives in `/var/lib/private/axophyte/axophyte.sqlite`; source refreshes do not remove it.

## Behavior

- **Soul:** [`src/soul.ts`](src/soul.ts) holds identity, voice, and a few voice exemplars, distilled locally from Toph's own Discord messages: a blunt, deadpan, slightly chaotic regular in his voice who never claims to be him. Lowercase, light punctuation, one or two lines by default, up to four sentences when explaining. No technical setup. `src/conversation/prompt.ts` owns chat formatting, speaker attribution, and trust boundaries, followed by place, date, server emoji, conversation memory, and people notes. A reaction is the minimum reply.
- **Self-knowledge:** the parameterless `self_info` tool in [`src/tools/self.ts`](src/tools/self.ts) supplies setup facts on demand: author, local inference, the model actually serving the turn, external services, message visibility, memory, commands, and capabilities. Facts stay out of the standing prompt; keep the tool's facts in sync with runtime behavior and this README.
- **Where it talks:** every message in its server's forum, if that server has one; anywhere else in a configured server, only when `@Axophyte` is mentioned or someone replies to it (no ping needed). Someone already in the current exchange can follow up without mentioning it. `@everyone` and role pings never trigger it.
- **Bursts:** it waits until people stop sending and typing (4 s quiet, 10 s after typing, at most 45 s) and answers exactly the messages that triggered it, by ID. A message arriving before substantive text, a saved note, or reaction submission restarts the wait; after that it queues separately. Reaction success is counted only after Discord confirms it; a failed submission returns a tool error without reopening the turn. Whitespace-only streamed deltas stay buffered without clearing the waiting notice or counting as output.
- **Forum memory:** each forum post is one conversation; older messages compact into persistent memory against the selected model's runtime context, reserving 8,192 answer tokens plus 1,024 headroom. Outside the forum it reads the triggering messages, up to 20 messages before them from the last 30 minutes, and the reply chains they point into (up to 10 older messages); it keeps no conversation memory there.
- **Conversation view:** every trigger message gets a tag (`m1`, `m2`, …) in every channel. Consecutive human lines share one model message; Axophyte's replies stay unlabeled. Human lines show Puerto Rico time (`America/Puerto_Rico`, UTC−4 year-round), with Today/Yesterday/day-age labels on the first line and day changes; exact multiples of seven days use weeks. Search hits and calendar-date filters use the same clock. Reply quotes and reaction counts include its own reactions. Images attach to their line when supported.
- **Emoji:** custom emoji appear to the model as `:name:`; the system prompt lists up to 100 usable emoji, Axophyte's own application emoji first (uploaded in the Developer Portal, usable in every server, never cut by the limit), then the server's, each with a one-line description of what it shows or how the server uses it. Own emoji are fetched at startup only: Discord sends no events for them, so new uploads need a restart. The model writes descriptions itself by looking at each emoji (first frame if animated) and its name, one at a time on the shared queue so replies wait behind at most one. Descriptions queue at startup and on server emoji creation/update, never after ordinary chat turns; a failed item is skipped until another update or restart, without blocking later emoji. It redoes its own after a rename. An admin's `/emoji` description replaces the model's and is never overwritten. Deleted emoji lose their notes immediately; startup removes stale notes after a successful emoji refresh. Deletion or rename during inference cannot save a stale description. Descriptions live in SQLite, per server; own emoji share one set across servers. When sent, `:name:` (closing colon optional, case-insensitive, one typo tolerated) becomes the real emoji, unless conversion would exceed Discord's message limit. Trailing emoji after text go out as a separate message so Discord shows them large.
- **Person memory:** per server: notes and nicknames learned in one server never load in another. It notes what people share about themselves (interests, projects, how they like to talk) as it comes up, so later conversations can build on it; only in channels every member of that server can read. Each note names the message it came from and is stored under that message's author, so nobody can write notes about someone else. Notes load wherever that person talks or is mentioned in the same server. Over 2,000 characters, the model condenses them to about 1,200, keeping what helps conversation over trivia.
- **Tools:** `react` targets a tagged trigger message with a server or unicode emoji (up to 3 per turn). Its required `reply` flag says whether a message follows. A round whose tool calls are all actions (`react`, `remember`, `revise`) ends the turn once it has written text, or reacted with `reply: false`, because forcing another round only makes the model repeat itself or pad with a lone "."; otherwise it keeps going and writes the message. Also `web_search`, `open_url` (through Tavily Extract; the bot never fetches pages itself), and `search_server` / `read_conversation`. Server search covers the current channel too (minus messages already in view) and only returns channels that everyone who can see the current channel can also read, whoever asks; it is off in private threads. Every round offers the same tools; per-turn budgets and, after 6 tool rounds, every further call are refused with an error telling the model to answer from what it has. It only gives up after 2 refused rounds.
- **Commands:** `/search query:` answers from a web search in any channel; `/memory show` lists your notes in this server; `/memory forget item:<number|all>` deletes them; `/emoji emoji: use:` (server admins only, checked again at runtime) sets what an emoji means; its autocomplete lists the server's emoji and Axophyte's own (which admins can't pick from their emoji menu). A meaning set for an own emoji applies in every server. `/retry` (server admins only, checked again at runtime) answers the channel's newest human message as if it just arrived, for when Axophyte never replied or its reply was deleted; it goes through the usual burst wait and deletes nothing. Command replies are ephemeral, so commands never enter conversation history. All servers share one model queue and one Tavily quota.
